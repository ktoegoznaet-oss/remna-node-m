# Настройка на стороне панели Remnawave

Сервер с нодой — это только транспорт. Пользователи, инбаунды и ссылки
подписок живут в панели. Ниже — что именно там нужно сделать, чтобы связка
с nginx на 443 заработала.

Порядок важен: сначала конфиг, потом нода, потом хосты.

---

## 1. Создать ноду и забрать SECRET_KEY

**Nodes → Create node**

| Поле | Значение |
|---|---|
| Name | произвольное, например `msk-01` |
| Address | публичный IP сервера с нодой |
| Port | значение `NODE_PORT` из `.env` (по умолчанию `2231`) |

После создания панель покажет `SECRET_KEY` — длинную base64-строку. Это
сертификат ноды, а не пароль. Скопируйте его в `.env` на сервере:

```bash
SECRET_KEY=<вставить сюда>
```

Панель подключается к ноде сама, по адресу `Address:Port`. Значит, порт
`NODE_PORT` должен быть доступен с IP панели — и больше ни с какого
(`scripts/firewall.sh` это настраивает).

---

## 2. Залить конфиг Xray

**Config Profiles → создать профиль** (в старых версиях — раздел
редактирования Xray-конфига).

Вставьте содержимое сгенерированного файла `xray/xray-config.json`
**целиком**, затем привяжите профиль к созданной ноде и включите все три
инбаунда.

Проверьте после сохранения, что панель не переписала ключевые поля:

```jsonc
"listen": "127.0.0.1"              // инбаунд не должен слушать 0.0.0.0
"sockopt": {
  "acceptProxyProtocol": true      // без этого клиенты будут видны как 127.0.0.1
}
```

Панель добавит к конфигу свои служебные секции (`api`, `policy`, `stats`) —
так и должно быть, не удаляйте их.

---

## 3. Создать хосты

**Hosts → Create host**, по одному на каждый инбаунд. Это самая
ответственная часть: именно отсюда собирается ссылка, которую получит
пользователь.

### Общее для всех трёх хостов

| Поле | Значение | Почему так |
|---|---|---|
| **Port** | **443** | Инбаунд слушает 4433/5443/8443, но клиент обязан идти на 443 — там nginx. Это главное поле во всей схеме. |
| Address | IP ноды или любой домен, указывающий на него | При Reality домен в TLS не участвует, он нужен только вам для удобства |
| Fingerprint | `chrome` | Маскировка отпечатка TLS-библиотеки |
| Public Key | публичный ключ соответствующего инбаунда | Панель обычно вычисляет его из приватного сама. Если поле есть и пустое — вставьте значение, выписанное при `gen-reality-keys.sh` |
| Short ID | `SHORT_ID_*` из `.env` | Должен совпадать со значением в конфиге инбаунда |

### Различия по инбаундам

| Инбаунд | SNI | Дополнительно |
|---|---|---|
| `VLESS_TCP_REALITY` | значение `SNI_TCP` | Flow: `xtls-rprx-vision`, если поле есть |
| `VLESS_GRPC_REALITY` | значение `SNI_GRPC` | Path / serviceName: значение `GRPC_SERVICE_NAME` |
| `VLESS_XHTTP_REALITY` | значение `SNI_XHTTP` | Path: значение `XHTTP_PATH` |

> **SNI в хосте обязан совпадать с ключом в `map` файла `nginx.conf`
> символ в символ.** Это одно и то же значение, оно приходит из `.env`.
> Расхождение здесь — причина примерно всех обращений «настроил, но не
> работает»: трафик молча уходит в `default`, и живым остаётся один инбаунд
> из трёх.

---

## 4. Проверить результат

1. В панели нода должна стать **online** в течение минуты после
   `docker compose up -d`.
2. Выдайте себе тестовую подписку и откройте ссылку в клиенте. В строке
   подключения должен стоять **порт 443**.
3. На сервере запустите `./scripts/check.sh` — раздел «Маршрутизация по SNI»
   покажет, разводятся ли соединения по разным инбаундам.
4. Подключитесь клиентом и посмотрите в панели раздел онлайн-пользователей:
   там должен быть **ваш реальный IP**, а не `127.0.0.1`. Если `127.0.0.1` —
   рассинхрон `proxy_protocol` / `acceptProxyProtocol`, см.
   [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

---

## Если меняете маскировочный домен

Домен участвует в трёх местах, и менять его нужно во всех сразу:

1. `.env` → `SNI_*`
2. `./scripts/configure.sh` → перегенерирует `nginx.conf` и `xray-config.json`
3. `docker compose restart nginx` + обновить конфиг в панели + поправить SNI
   в соответствующем хосте

Старые подписки после смены SNI перестанут работать — клиентам нужно
обновить конфигурацию.
